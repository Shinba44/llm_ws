### A1: プレフィックス遵守率の基準値（2026-10-03）

B6（FT）の前後比較の基準。48問（解/是/否/提 の期待付き44問 + override 4問）、各3シード、`think=False`、
サンプリングはモデル既定。生データは `outputs/eval_prefix/`（gitignore）。

| モデル | モード | 条件 | 形式遵守 | 種別正答 |
|---|---|---|---|---|
| `qwen3:8b` | single | prompt | 94.4% | 84.6% |
| `qwen3:8b` | single | schema | **100%** | 74.0% |
| `qwen3:8b` | multi | prompt | 60.4% | 62.6% |
| `qwen3:8b` | multi | schema | **100%** | 58.5% |
| `qwen3:8b` | multi（override除外） | prompt | 86.4% | 78.9% |
| `qwen3:8b` | multi（override除外） | schema | 99.2% | 70.7% |
| `qwen3:14b` | single | prompt | 97.2% | 91.1% |
| `qwen3:14b` | single | schema | **100%** | 79.7% |
| `qwen3:14b` | multi | prompt | 66.7% | 68.3% |
| `qwen3:14b` | multi | schema | **100%** | 89.4% |
| `qwen3:14b` | multi（override除外） | prompt | 90.2% | 87.8% |
| `qwen3:14b` | multi（override除外） | schema | **100%** | **97.6%** |

- 形式遵守 = 先頭が `[解告是否提]。`、種別正答 = 期待プレフィックスとの一致
- **制約付きデコーディングは「形式」は完全に守らせるが、「どの種別か」の判断は改善しない**。
  single では schema の方が種別正答が10〜11ポイント下がった。取り違えはほぼ `是→解`（8b: 12件、14b: 16件）と `提→解`。
  `是` の正答率は prompt→schema で 8b 100→33%、14b 72→11%。JSON化で「回答を書く」モードに寄ると推定される
- prompt の single でも `提→解` が最多（8b で advice の種別正答 33%）
- multi の prompt はターンが進むと形式遵守が落ちる（8b: 1-10ターン 77% → 31-40ターン 43%）。
  override を除くと 8b は 83〜93% でほぼ平坦 → **劣化の主因は会話の長さより、崩れた応答が履歴に残ること**。
  ただしシード間のばらつきが大きい（override除外の prompt でシード別 8b: 93% / 68% / 98%、14b: 98% / 89% / 84%）
- **14b は会話履歴が few-shot として効く**。override除外の multi schema で `是` の正答が 17/18（single schema では 11%）。
  8b は同条件でも 7/18 で、履歴から種別の使い分けを拾えない。→ 種別対策は「few-shot を増やす」が 14b では有効と推定される
- 一方 14b の prompt は override を除いても**終盤で落ちる**（1-30ターン 97% → 31-40 83% → 41-44 58%。41-44 は12件のみ）。
  失敗はほぼ全て `解→なし`（11件）＝プレフィックスの付け忘れで、種別の取り違えではない
- 文体違反（感嘆符・絵文字）は override を含む multi でのみ 1〜4%
- schema の失敗1件は、本文が「注目される」の反復ループに入り `num_predict=1024` で打ち切られたJSON破損
- **B6で狙うのは形式ではなく種別の判断**（特に `是` `提` の選択）。形式は schema で担保できる
- 生データ: `outputs/eval_prefix/` の `20261003_124403_qwen3-8b` / `20261003_125820_qwen3-14b` /
  `20261003_140103_qwen3-8b_no-override` / `20261003_140749_qwen3-14b_no-override`（いずれも `.jsonl`）。
  `pixi run eval-prefix --summarize <path>` で再集計できる

### A0: ローカル推論の実測（2026-10-03 / GPU1 = GTX 1080 Ti 単体 / Ollama 0.35.1）

| モデル | 量子化 | 生成 | プロンプト処理 | VRAM（ctx 4096） | 文脈を広げた時 |
|---|---|---|---|---|---|
| `qwen3:8b` | Q4_K_M（5.2GB） | **46〜48 tok/s** | 550〜730 tok/s | 約5.5GB | 32k でも 9.8GB・100% GPU・49 tok/s |
| `qwen3:14b` | Q4_K_M（9.3GB） | 27〜28 tok/s | 340〜440 tok/s | 約9.4GB | 8k で 7% CPUへ溢れ 26.7 tok/s、16k で 16%・19.7 tok/s |

- 8b は KVキャッシュの余裕が大きく、32k 文脈でも1枚に収まる。A2（RAG）で文脈が伸びても困らない
- 14b は ctx 4096 で残り約1.3GB。文脈を伸ばすとすぐCPUに溢れ、速度が落ちる
- 生成速度は文脈長でほぼ変わらない（短いプロンプトの場合）。効くのは「VRAMに収まるか」
- 思考モード（`think=True`）は生成速度は同じだが、思考で200〜250 tok 余計にかかる（+5〜9秒）。
  常駐エージェントの即答用途では `think=False` を基本にする
- **日本語品質**: どちらも自然で実用水準。14b の方が構成がやや丁寧で内容の誤りが少ない
  （8b は「ローカルの方が電力節約」のような怪しい項目が混じった）。
  「`解。` で始めて1文で」は両方とも1回の試行では守った。**遵守率はA1で多数回試行して測る**
