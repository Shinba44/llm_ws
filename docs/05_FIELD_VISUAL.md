# 解析フィールド 視覚仕様

エージェントが解析中であることを示す視覚表現の仕様。
[00_PLAN.md](00_PLAN.md) の **A5（常駐と能動通知）** で用いるUIの元になる。

このファイルの数値だけで同じものを再構築できるように、定数と算出式をすべて記載する。

**参照実装**: [assets/field_demo.html](assets/field_demo.html)
外部依存のない単一ファイル。ブラウザで直接開けば動く。

```bash
xdg-open docs/assets/field_demo.html
```

---

## 1. 設計要件

この4点が満たされていなければ、実装が仕様から外れている。

| # | 要件 | 判定方法 |
|---|---|---|
| R1 | **幾何学的**であること | 曲線を描かない。直線と多角形のみで構成する |
| R2 | **不定形**であること | 対称形にならない。同じ形状が繰り返し現れない |
| R3 | **図形内に文字を置かない** | 描画コードに文字描画APIが存在しない |
| R4 | **寒色と暖色が同時に存在する** | 任意の1フレームを切り出して両方が確認できる |

R1の帰結として、**円を描画しない**。結節点や頂点のマーカーは正方形を使う。
R2の帰結として、同心円・放射対称・繰り返しパターンを使わない。

## 2. 空間モデル

透視投影を自前で持つ。3Dライブラリは使わない。

```
DEPTH = 340          // z の広がり（±）
FOV   = 760

scale = min(W / 900, H / 620) * 1.5
cx    = W / 2
cy    = H / 2 - 14
```

投影は Y軸回転（yaw）→ X軸回転（pitch）→ 透視除算の順。

```
X = x·cos(yaw) - z·sin(yaw)
Z = x·sin(yaw) + z·cos(yaw)
Y = y·cos(pitch) - Z·sin(pitch)
Z = y·sin(pitch) + Z·cos(pitch)

s = FOV / (FOV + Z + DEPTH · 0.55)      // 深度係数。線幅・不透明度・サイズに乗算する
screen = (cx + X·s·scale,  cy + Y·s·scale)
```

視点の動き:

```
t     += dt · 0.9
yaw   += dt · 0.055 · (0.4 + drift · 0.4)
pitch  = sin(t · 0.14) · 0.14
```

## 3. 要素

描画順は **走査面 → 破片 → 格子 → 多角形 → 波面**。奥のものから重ねる。

### 01 hull — 不規則多角形（中心モチーフ）

3枚。頂点数を素数寄りにし、対称形になる組み合わせを避ける。

| # | 頂点数 | 基準半径 | z | speed |
|---|---|---|---|---|
| 0 | 11 | 208 | 0 | 1.0 |
| 1 | 7 | 132 | −70 | 1.35 |
| 2 | 5 | 268 | 90 | 0.7 |

頂点ごとに以下を**生成時に乱数で固定**する。これが不定形の根拠になる。

```
base = (i / n)·2π + rand(-0.22, 0.22)     // 角度の初期ばらつき
r    = 基準半径 · rand(0.62, 1.0)          // 半径のばらつき
amp  = rand(0.14, 0.42)                   // 半径の揺れ幅
w    = rand(0.25, 0.85) · speed           // 角周波数
ph   = rand(0, 2π)                        // 位相
wob  = rand(0.1, 0.35)                    // 角度の揺れ幅
zAmp = 基準半径 · rand(0.08, 0.3)          // 奥行きの揺れ幅
```

毎フレームの頂点位置:

```
r_t = r · (1 + sin(t·w + ph) · amp)
a_t = base + sin(t·w·0.6 + ph·1.7) · wob
z_t = z + sin(t·w·0.8 + ph) · zAmp
点  = (cos(a_t)·r_t,  sin(a_t)·r_t,  z_t)
```

**頂点ごとに w と ph が異なるため位相が揃わず、対称形に戻る瞬間が存在しない。**

描画:

```
fade      = 1 - index · 0.22
lineWidth = (1.9 - index · 0.4) · (0.7 + glow · 0.4)
線の不透明度 = 0.5 · fade · (0.45 + glow · 0.5)      明度 64
頂点マーカー = 一辺 3.2·s の正方形、不透明度 0.85·fade、明度 70
```

### 02 lattice — 近接グラフ

結節点120個。**辺は保持せず、毎フレーム距離しきい値で張り直す。**
点が漂うため接続が生成・消滅を繰り返し、格子の形が固定されない。

初期配置と移動:

```
位置  x ∈ [-330, 330],  y ∈ [-230, 230],  z ∈ [-DEPTH, DEPTH]
速度  vx, vy, vz ∈ [-1, 1],  ph ∈ [0, 2π]

ph += dt · 0.4
x  += vx · drift · dt · 26
y  += (vy + sin(ph)·0.3) · drift · dt · 26
z  += vz · drift · dt · 26

反射境界: |x| > 380 → vx 反転 / |y| > 270 → vy 反転 / |z| > DEPTH → vz 反転
```

結線判定は**投影後の画面距離**で行う（奥行きが近さに反映される）:

```
lim = link · scale
d   = 画面上の2点間距離
d ≤ lim のとき結線する

near      = 1 - d / lim
depth     = (s_a + s_b) / 2
flare     = max(hit_a, hit_b)                    // 走査面との近さ（§3-04）
lineWidth = 0.6·depth + flare·0.8
不透明度   = near·0.3·depth·(0.5 + glow·0.5) + flare·0.35
```

結節点の描画（正方形）:

```
一辺     = (1.6 + hit·3.4) · s
不透明度 = (0.32 + hit·0.6) · min(1, s·1.2)
明度     = 62 + hit·12
```

計算量は O(n²) = 7,140 ペア。`|dx| > lim || |dy| > lim` の早期棄却を先に置くこと。

### 03 shards — 多面体の破片

7個。**頂点配置を起動ごとに乱数生成するため、読み込むたびに形が違う。**

```
頂点数 n = round(rand(5, 9))
size     = rand(26, 62)

各頂点（球面上のランダム点）:
  θ = rand(0, 2π),  φ = acos(rand(-1, 1)),  r = size · rand(0.55, 1)
  (r·sinφ·cosθ,  r·sinφ·sinθ,  r·cosφ)

辺: 全頂点対のうち距離 < size · 1.25 のものだけを結ぶ
    → 完全グラフにならず、破片ごとに異なる不規則ワイヤーフレームになる

中心 cx ∈ [-360,360], cy ∈ [-240,240], cz ∈ [-DEPTH, DEPTH]
回転軸係数 ax, ay, az ∈ [-0.4, 0.4]
a += dt · 0.35 · drift        // 3軸に a を掛けて回転行列に渡す
mix = random()                // 色相の混合比（§4）。生成時に固定
```

描画: `lineWidth = 0.9·depth`、不透明度 `0.28·depth·(0.5 + glow·0.5)`、明度 58。

### 04 plane — 走査面

空間を上下する水平面。通過した結節点だけが発光する（§3-02 の `hit`）。

```
scanY ∈ [-250, 250] を往復
scanY += 向き · scanV · dt · 300

hit = max(0, 1 - |node.y - scanY| / 52)

四隅 = (±400, scanY, ±DEPTH) を投影して四角形を描く
枠  : 不透明度 0.16 + glow·0.14、明度 60
塗り: 不透明度 0.035 + glow·0.03、明度 55
```

### 05 burst — 状態遷移時の波面

**円ではなく不規則な9角形**。等方的に広がると魔法陣に見えるため、半径を頂点ごとに変える。

```
burst は 1 から始まり、burst -= dt · 1.1 で減衰
r  = (1 - burst) · max(W, H) · 0.75
i 番目の頂点:
  a  = (i / 9) · 2π
  rr = r · (0.78 + sin(i·2.3 + t) · 0.22)
  点 = (cx + cos(a)·rr,  cy + sin(a)·rr·0.72)      // 縦を 0.72 倍して扁平に

lineWidth 1.4、不透明度 burst · 0.5、色相は暖色極
```

## 4. 配色システム

### 4.1 2極方式

色相を単一の値で回すと「今は青／今は赤」と切り替わるだけになる。
**独立に漂う2つの色相極を別々の要素に割り当てる**ことで、常に寒色と暖色が同居する（R4）。

| 極 | 範囲 | 割り当て |
|---|---|---|
| 寒色極 `coolHue` | 168–262°（シアン〜青紫） | 格子の結節点・辺、走査面（+30°） |
| 暖色極 `warmHue` | 335–70°（マゼンタ〜赤〜橙〜黄） | 多角形3枚（+14°ずつずらす）、波面 |
| 補間 | 2極の間 | 破片。個体ごとに固定の `mix` で補間するため寒色寄りと暖色寄りが散在する |

### 4.2 擬似ノイズによる漂い

周期の噛み合わない正弦波3本を合成する。**周波数比が無理数に近いため位相が揃わず、
同じ配色の瞬間が繰り返されない。**

```
wobble(u, seed) = 0.62·sin(u·0.041   + seed)
                + 0.27·sin(u·0.0977  + seed·2.3)
                + 0.11·sin(u·0.2131  + seed·4.1)          // おおよそ [-1, 1]

hueT    += dt · hueSpd
warmHue  = 22  + 48 · wobble(hueT, 3.7)
baseCool = 215 + 47 · wobble(hueT, 0.0)
coolHue  = lerpHue(baseCool, warmHue - 38, warmPull)       // 通知時は寒色極も暖色へ寄る
```

シードが異なるため2極は独立に動く。

### 4.3 色相の補間と明度補正

角度の補間は必ず最短経路で行う（0°/360° の境界で破綻させない）:

```
lerpHue(a, b, k) = a + (((b - a + 540) mod 360) - 180) · k
```

色の生成（彩度は既定88%、明度は既定62%）:

```
hsl(h, alpha, l = 62, s = 88):
    h = ((h mod 360) + 360) mod 360
    if 34 < h < 82:  l -= 10        // 黄色域は同じ明度でも明るく見えるため落とす
    return hsla(h, s%, l%, alpha)
```

### 4.4 変調

- **奥行き変調** — 結節点の色相は `coolHue + (z / DEPTH) · 22`。手前と奥で色が変わり体積感が出る
- **走査時の暖色寄り** — 走査面が触れた辺は `lerpHue(色相, warmHue, flare·0.55)`、
  結節点は `lerpHue(色相, warmHue, hit·0.7)`。「解析の熱が走る」表現

### 4.5 固定色

背景と意味色は漂わせない。

| 用途 | 値 |
|---|---|
| 背景（最暗部） | `#04070e` |
| 背景（上部） | `#08121c` |
| 罫線 | `#16334a` |
| 本文 | `#e2f4ff` |
| 補助文字 | `#6a8399` |
| `告。` | `#ffa94d` |
| `提。` | `#6fe7c0` |
| `否。` | 補助文字と同じ |

意味色（告／提／否）はアクセント色とは独立に保つ。漂う色相に巻き込むと意味が読めなくなる。

## 5. 状態

3状態。各パラメータは切り替え時に即値を代入せず、指数緩和で補間する。

```
ease(現在値, 目標値, dt, k) = 現在値 + (目標値 - 現在値) · min(1, dt·k)
```

| パラメータ | 待機 | 解析中 | 通知 | 緩和係数 k |
|---|---|---|---|---|
| `drift` 移動速度 | 0.30 | 1.70 | 0.75 | 2.2 |
| `link` 結線しきい値 | 76 | 104 | 84 | 2.2 |
| `scanV` 走査速度 | 0.16 | 0.95 | 0.42 | 2.2 |
| `glow` 発光量 | 0.50 | 1.25 | 1.00 | 2.6 |
| `hueSpd` 色相の漂う速さ | 1.0 | 2.4 | 1.5 | 1.6 |
| `warmPull` 暖色への引き寄せ | 0 | 0 | 1 | 1.2 |

状態を切り替えたら `burst = 1` を設定して波面を発生させる。

## 6. 実装上の注意

| 項目 | 内容 |
|---|---|
| 解像度 | `devicePixelRatio` を上限2でクランプし、`setTransform(dpr,0,0,dpr,0,0)` |
| リサイズ | `ResizeObserver` で追従。キャンバス実サイズとCSSサイズを分けて扱う |
| CSS変数の更新 | 毎フレームだと再計算が無駄。**80ms間隔に間引く** |
| 文字列生成 | 辺ごとに色文字列を作るので、早期棄却を必ず先に置く |
| モーション配慮 | `prefers-reduced-motion` で時間の進行を止め、静止構図として成立させる |
| 依存 | 外部ライブラリ・外部フォントを使わない（CSPの厳しい環境でも動くこと） |

## 7. 常駐オーバーレイ化

A5でデスクトップに常駐させる場合の実装先。

| 環境 | 方法 |
|---|---|
| Electron | `transparent: true` + `frame: false` + `alwaysOnTop: true` + `setIgnoreMouseEvents(true)` |
| PyQt / PySide | `Qt.WA_TranslucentBackground` + `Qt.FramelessWindowHint` + `Qt.WindowStaysOnTopHint` |
| Wayland | `gtk-layer-shell` でオーバーレイレイヤーに配置 |

Python主体のプロジェクトなので PyQt が親和的だが、この仕様はCanvas前提で書かれているため
Electron で HTML をそのまま載せるのが最短。PyQt に移す場合は `QPainter` で
§2〜§4 の式を再実装する。

## 8. 再現チェックリスト

- [ ] 描画コードに文字描画API（`fillText` / `strokeText` / `textPath`）が存在しない（R3）
- [ ] 円弧API（`arc` / `ellipse`）を使っていない。頂点マーカーが正方形である（R1）
- [ ] 多角形の頂点が個別の周波数と位相を持ち、対称形が現れない（R2）
- [ ] 静止画を1枚切り出したとき、寒色と暖色が同時に写っている（R4）
- [ ] 再読み込みすると破片の形が変わる
- [ ] 状態を切り替えると波面が出て、各パラメータが緩和補間される
- [ ] `prefers-reduced-motion` で静止しても構図が成立する
